# Runnable voice library

Goal: `libvoice_en_gb_amy.so` built from source, so that no original binary is loaded at all.
This is step 1 of porting: both a native Linux build and an arm64 Android build need the voice
library as source. The matching decompilation keeps going alongside it.

## How it is checked

Synthesis is deterministic: the same text always gives byte-identical audio. So the decompiled
voice library has to reproduce the original's output exactly, not just sound right.

```
tools/difftest.sh                     # corpus spoken with original and decompiled voice libraries
./speak --voice-lib decomp "text" x.wav
```

- **The test.** `tools/difftest.sh` speaks every line of `tests/run/corpus.txt` with the same
  (decompiled) engine twice: once with `target/libvoice_en_gb_amy.so` and once with the
  decompiled build. The WAVs must be identical.
  - The corpus covers plain words, punctuation and phrasing, numbers, dates, times, money,
    abbreviations, acronyms, symbols, foreign words, the lang.dat PLS words and a long paragraph.
  - Add a line whenever a bug shows up that the corpus missed.
- **Sanity check.** Original against original gives 23/23.
- **Build.** `tools/build_runnable.py -b libvoice_en_gb_amy` writes
  `build/voice/libvoice_en_gb_amy.so`. It keeps the original's four exports (`register_voice`,
  `unregister_voice`, `language_data`, `TTS_ENGINE_1_6`) and reports what is still undefined.
- **Shared sources.** Many of the voice library's functions are compiled from engine sources (the
  embedded Flite, string and vector utilities). Where two credited files define the same
  function, the build weakens the copy the function table does not credit, so the table decides.

## Inventory (2026-10-29)

- **Size.** 1790 functions, 0xd7d40 bytes of code.
- **Library code, verified by `dc libmatch`.** 70.8% of the bytes, the voice library's own copies of:
  - PCRE 8.37 (239 functions)
  - SILK 1.0.8 (70)
  - cmp v16 (166)
  - libgcc
  The same `cmp` leftovers as in the engine remain (byte-order helpers, `cmp_read_object`).
- **IVONA's own code.**
  - 611 functions match; 66 are `wip`.
  - About 550 are `todo`, roughly 260 KB, mostly at 0x28000–0x68000:
    - text analysis, lexicon and letter-to-sound, postlex, prosody (CART, durations, DNN models),
      unit selection, the vox database;
    - a cluster of about 100 small functions at 0xe7000–0xf0000, not identified yet.

## Approach

1. **Link.** Grow the set of functions until the library links. `--gc-sections` keeps only what is
   reachable from `register_voice`, through code and data, so the undefined list grows as data
   tables (lexicon, CART trees, module tables) are defined.
2. **Write functions to match where practical, correctly always.** Functions that already match
   are correct by construction. A non-matching one is accepted when the difftest passes.
3. **Data.** Generate static tables with `./dc dump`, not by hand. `amy_lexicon` (0x3bb67c) is
   the big one.
4. **Stubs.** None until the library links. If one is needed for a step, it goes in
   `src/libvoice_en_gb_amy/runnable_stubs.c` and is listed here.

## Status (2026-10-29)

- **Parity.** The library links and speaks, and `tools/difftest.sh` gives 23/23 byte-identical
  WAVs (the corpus plus homograph lines). Bugs the difftest found on the way:
  - `lts_apply` must split "k-s" style LTS phones with libc `strchr`. IVONA's `cst_strchr`
    returns the terminator when the character is missing, which split every phone in two.
  - IVONA's regexp has 19 capture groups: `CLOSE` is 40 and `CST_NSUBEXP` 20 (Flite: 30, 10).
    Compiled regexes with groups (`en_rx_have`) failed with "memory corruption".
  - `cst_error()` is `exit(-1)`, so a voice failure looks like a silent exit status 255.
    `IVONA_DEBUG_EXIT=1 ./speak ...` prints a stack scan of whoever called `exit()`.
- **Functions.** 784 match, 152 are `wip` (compiled from source, not matching), 296 `todo`
  (~165 KB) are not in the build. `--gc-sections` shows they are not reachable from the exports
  through anything already written.
- **The English language module:**
  - `en_lang.c`: the descriptor, init/fini, phone numbers; `en_setup.c`: lexicon setup by code.
  - `en_gb_lex.c`, `en_us_lex.c`: lexicons over the language file's entries, addenda, LTS.
  - `en_word.c`: pronunciation of words the lexicon lacks; `en_ffeatures.c`: gpos and lex_pos.
  - `en_token.c`, `en_number.c`, `en_text.c`: text normalization (numbers, dates, money,
    abbreviations, ...).
  - `en_postlex.c`: syllabification (`postlex_apply_rules` in cst_postlex.c, a CART), Amy's
    post-lexical rules; `en_tone.c`: phrase-final tones; `en_xsampa.c`: X-SAMPA input.
  - Data: generated by `tools/gen_*.py` (phonesets, rewrite rules, syllable CARTs, regexes, gpos,
    tables); the LTS trees and the 2.3 MB en-US POS lexicon are extracted from `target/` at build
    time (`config/libvoice_en_gb_amy.assets.yaml`, `tools/gen_assets.py`).
- **`en_word_pos`** (0x3d908..0x482c8, 0xa9c0 bytes) holds the homograph part-of-speech
  rules (read/read, content, bass, ...): about 780 neighbour-word tests over 190 word lists. It
  is one function: the splitter had cut it into five rows at literal pools, now merged.
  - Source: `src/libvoice_en_gb_amy/en_word_pos.c`, a normal C file. Its first draft was
    generated from the binary by `tools/asm2c.py --readable`, so it is exact but still
    goto-style with register-style names. Hand cleanup is open; `wip` at 20%.
  - Check build: `tools/build_runnable.py -b libvoice_en_gb_amy -D IVONA_CHECK_WORD_POS` links
    the original's code too (lifted by `tools/asm2c.py`) and `tests/run/check_word_pos.c`
    compares both on every word, aborting on a difference. The lifted copy counts block
    coverage into `$IVONA_COVERAGE`. `tests/run/gen_word_pos_text.py` writes text from the
    rules' own words. No differences on the corpus (332 words) or 400 generated sentences
    (693 of 1092 blocks reached); keep generated batches small (one utterance each run).
- **Stubs** (`src/libvoice_en_gb_amy/runnable_stubs.c`): `en_token_say_as`, which is SSML only
  (`docs/notes/ssml-deferred.md`), so the original returns 0 here too.
- **Unverified shared code.** `str_ctx_match*`/`str_rewrite_span` (engine `syllabify.c`) score
  low in both binaries. They run for X-SAMPA conversion, which the corpus does not exercise
  (SSML).
- **TU boundaries** of the English module are guesses. Its data (0x3ba81c..0x3c2f64) is one
  contiguous region, so several of these files may be one original TU.
